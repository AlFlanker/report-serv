# Сервис формирования отчётов

Angular 22 + **ng-zorro-antd**, Node.js 24, SQLite и ExcelJS.
Реализованы сценарии из предоставленных макетов «ЛК ЭБ · Формирование отчетов».
Обращения к БД целевых систем заменены подготовленными JSON-ответами.

## Запуск

Требуются Node.js **24.15+ в ветке 24** и npm. Внешняя БД и секреты не нужны.

```bash
npm ci
npm start
```

Интерфейс работает на порту **4200**, API — **3001**. Сервер Angular проксирует
`/api/**` на backend. Команда запускает оба процесса; Ctrl+C останавливает оба.

```bash
npm run build       # production-сборка интерфейса
npm run start:prod  # API и собранный интерфейс на одном порту 3001
npm test           # проверки сервера, очереди, фильтров и Excel
npm run test:e2e    # сценарии в Chromium, отдельные порты 4310/4311 и временная БД
```

Для браузерных проверок используется `/usr/bin/chromium`, если он установлен.
В другом окружении выполните `npx playwright install chromium` либо задайте
`CHROMIUM_PATH`. Результаты неудачных проверок сохраняются в `test-results/`.

## Возможности

- Каталог шести отчётов, выбор параметров и постановка задания в очередь.
- Поиск по названию/номеру, фильтры статуса и даты создания, сортировка и страницы.
- Двухшаговое окно создания; проверка обязательных полей, порядка дат и длины периода.
- Ночное выполнение свода операций: **00:00–06:00 МСК**. Начало зависит от очереди.
- Состояния «В очереди», «Выполняется», «Завершено», «Ошибка», карточки подробностей.
- Настоящие `.xlsx` с листами **«Параметры»** и **«Данные»**. Размер и число строк
  вычисляются по сформированному файлу, поэтому отличаются от демонстрационных чисел макета.
- Сохранение заданий, файлов и уведомлений в SQLite; выполнение не зависит от вкладки.
- Восстановление прерванного выполняющегося задания после перезапуска сервера.
  Ошибочные задания автоматически не повторяются.
- Срок хранения файла — 7 дней; после истечения скачивание запрещено,
  фоновый обработчик удаляет содержимое файла, сохраняя историю задания.
- Уведомления о завершении и сведения об ошибке для копирования в поддержку.

## Данные и конфигурация

По умолчанию при первом запуске создаются шесть демонстрационных заданий
№1043–1048, включая пример ошибки формата. Времена создания привязаны к первому
запуску, чтобы задания попадали в фильтр последних семи дней. Их параметры
соответствуют макетам. Выполняющиеся примеры затем обрабатываются сервером.

`server/fixtures/*.json` содержит фиксированные ответы для октября–ноября 2026 года.
Адаптер `server/mock-source.mjs` проверяет структуру и фильтрует строки по периоду,
подразделению и лицевому счёту. Для остатков выбирается последний подготовленный
снимок не позднее указанной даты. За период без подготовленных данных создаётся
корректный Excel с заголовками и нулём строк. Новые задания реестра платежей
выполняются успешно; ошибка №1045 — отдельный сохранённый пример.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DB_PATH` | `.data/reports.sqlite` | Файл SQLite, включая очередь и Excel-результаты |
| `SEED_DEMO` | `true` | `false` создаёт пустой кабинет при первой инициализации БД |
| `MAX_PERIOD_DAYS` | `31` | Максимальный период включительно |
| `RETENTION_DAYS` | `7` | Хранение нового результата с момента завершения |
| `PORT` / `API_PORT` | `3001` | Порт API (`API_PORT` используется командой `npm start`) |
| `WEB_PORT` | `4200` | Порт интерфейса при `npm start` |

Пример запуска без начальных заданий, с отдельной БД:

```bash
SEED_DEMO=false DB_PATH=.data/empty.sqlite npm start
```

`SEED_DEMO` не очищает существующую БД. Данные находятся в игнорируемой Git
папке `.data/`. Для резервного копирования работающей SQLite используйте
SQLite backup API либо остановите сервер перед копированием файла.

## Устройство и границы

- `src/app/` — интерфейс и HTTP-клиент.
- `server/domain.mjs` — каталог, валидация, расчёт окна по Москве.
- `server/service.mjs` — SQLite, очередь, результаты и уведомления.
- `server/mock-source.mjs`, `server/fixtures/` — заменяемый адаптер целевых систем.
- `server/workbook.mjs` — генерация Excel.
- `server/index.mjs` — HTTP API и раздача production-сборки.
- `e2e/` — браузерные сценарии.

Это автономный сервис для **одного демонстрационного пользователя**, без
авторизации и интеграции с настоящим личным кабинетом. Уведомления доступны внутри
этого приложения. Запускайте один экземпляр backend на один файл SQLite.
Для внедрения потребуются интеграция с учётной записью ЛК, проверка прав на задания
и подразделения и замена адаптера целевых систем.

Исходная ссылка на обсуждение ChatGPT остаётся недоступной из среды; требования,
не отражённые в присланных изображениях, не считались подтверждёнными.

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/health` | Проверка доступности |
| `GET /api/catalog` | Отчёты, подразделения, лимиты, время сервера и ближайшее ночное окно |
| `GET /api/jobs` | Список: `search`, `status`, `createdFrom`, `createdTo`, `page`, `pageSize`, `sort` |
| `POST /api/jobs` | Создание: `{reportId, parameters}` |
| `GET /api/jobs/:id` | Состояние и параметры задания |
| `GET /api/jobs/:id/download` | Excel; 409 до готовности, 410 после истечения хранения |
| `GET /api/notifications` | Уведомления и число непрочитанных |
| `POST /api/notifications/read` | Отметка прочтения: `{ids: number[]}` |

Параметры периода: `startDate`, `endDate`, `department`; для оборотов также
`account` (11 цифр). Для остатков: `asOfDate`, `department`. Даты — `YYYY-MM-DD`.
Метки времени возвращаются в ISO UTC, интерфейс отображает их в МСК.
Ошибки имеют вид `{error: {code, message, fields?}}`.

В облачных задачах используйте существующий checkout `/workspace/report-serv`:
задачи уже изолированы, отдельный worktree не требуется.
