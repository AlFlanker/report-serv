# Сервис формирования отчётов

**Spring Boot 3.5.16 + Spring Batch 5.2.6**, Java 25, PostgreSQL 17, S3;
интерфейс — Angular 22 и **ng-zorro-antd** по предоставленным макетам.
БД целевых систем заменены подготовленными JSON-ответами.

## Запуск

Требуются Java **25**, Node.js **24.15+ в ветке 24**, npm, Docker Compose v2,
`curl` и `tar`. Скрипт скачивает Maven **3.9.16** с Maven Central, проверяет
SHA-512 и сохраняет его и зависимости в игнорируемой `.cache/maven`.
Если полный JDK 25 отсутствует, он извлекается из закреплённого Docker-образа
в `.cache/maven`. Скрипты сборки и локального запуска используют один JDK 25;
системная Java другой версии не мешает запуску. Для загрузки JDK нужен Docker.

```bash
npm ci
npm run infra:up       # PostgreSQL + S3, подготовка локальных credentials
npm start              # Java API :3001 + Angular :4200
```

Локальные пароль PostgreSQL и ключи S3 создаются в игнорируемом `.env`.
Повторная настройка сохраняет существующие значения и данные.
`npm start` собирает Java backend перед запуском; `/api/**` проксируется через
Angular. `API_PORT` и `WEB_PORT` позволяют изменить порты.

```bash
npm run build          # Angular
npm run build:api      # backend/target/report-serv.jar
npm run start:prod     # Java API + готовый UI на порту 3001
npm run docker:up      # собрать и запустить весь сервис в Docker
```

Docker запускает PostgreSQL → S3 и инициализацию бакета → Java-приложение.
UI включается в JAR, доступен на порту **3001**. Перед запуском освободите этот
порт и остановите другой backend той же схемы. Runtime образ содержит Java;
отдельный Node-контейнер выполняет только настройку S3.
Образы закреплены digest; приложение работает от непривилегированного пользователя.

Постоянные данные: volumes `postgres-data` и `s3-data`. `docker compose down`
сохраняет их; `down -v` удаляет. Старый `app-data` сохранён для резервных копий
SQLite и не используется приложением. PostgreSQL и S3 публикуются только на
loopback: порты **5432** и **9000**.

В среде с прокси Maven и Docker используют `BUILD_CA_CERT` или `CODEX_PROXY_CERT`
с проверкой TLS. Docker получает сертификат через BuildKit secret; `.env` и
секреты исключены из образов и Git. `MAVEN_EXECUTABLE` позволяет использовать
установленный Maven вместо загрузки дистрибутива.
Compose добавляет `s3` и `postgres` в `NO_PROXY`/`no_proxy`, чтобы Java обращалась к локальным сервисам напрямую.

## Задания и Spring Batch

Пользовательское задание сохраняет ID, параметры и **версию определения отчёта**.
Для него создаётся `JobInstance` Spring Batch с идентифицирующими параметрами
`jobId` и `definitionVersion`. Повторное выполнение создаёт новый `JobExecution`
того же экземпляра, без подмены параметров текущим временем.

PostgreSQL сохраняет `BATCH_JOB_*`, `BATCH_STEP_*`, `ExecutionContext`, историю
выполнений, пользовательские задания, уведомления и метаданные артефактов.
Промежуточные данные и итоговые Excel находятся в **S3**. В контекстах Batch
хранятся только ссылки, параметры и небольшие контрольные данные.

Каждый отчёт выполняется несколькими сохранёнными шагами. Полученные данные
фиксируются в S3 как JSONL: описание колонок и последовательность строк.
Генерация Excel читает сохранённый артефакт, затем публикация связывает готовый
файл с заданием. Версионированный план позволяет расширять цепочку шагами
преобразования и объединения данных для составных отчётов.

При ошибке пользователь открывает карточку и нажимает **«Возобновить выполнение»**,
если это действие доступно. Завершённые шаги переиспользуются; неуспешный шаг
выполняется заново. Незавершённый XLSX формируется заново из сохранённых данных.
Автоматического повторения бизнес-ошибок нет. Версия определения и срок хранения
промежуточных данных проверяются перед возобновлением.

В карточке показаны состояния шагов, время выполнения, попытки, фактические
счётчики и сведения об ошибках. История старых заданий сохраняется; для заданий,
созданных до перехода, шаги Spring Batch отсутствуют.

Один backend владеет одной схемой PostgreSQL через advisory lock. При потере
владения процесс останавливается, Compose перезапускает его. При запуске
восстанавливается состояние прерванных Batch-выполнений. Каждая попытка записи
имеет уникальный S3-ключ; поздняя очистка старой попытки не удаляет новый результат.

## Потоковая обработка и хранение

Excel записывается непосредственно в поток ZIP/OOXML: построчно, с inline-строками,
без полной книги в памяти и без временного файла. Не используется SXSSF с
промежуточными файлами. Поддерживаются листы «Параметры» и «Данные», типы ячеек,
заголовки и фильтры. Количество строк и размер соответствуют фактическому файлу.

S3 получает данные через multipart upload с ограниченными буферами. По умолчанию
часть — **8 МиБ**, параллелизм — **2**. Медленный S3 останавливает запись и чтение
источника. Память зависит от буферов и отдельной строки, а не от размера отчёта.
Фиксированные небольшие JSON-моки загружаются в память; настоящий адаптер может
выдавать данные курсором через тот же интерфейс.

Статус «Завершено» устанавливается после успешной загрузки и публикации результата.
Перед передачей объекта сохраняется намерение очистки; после успешного сохранения
метаданных оно снимается. Очистка при ошибках повторяется при доступности S3.
Lifecycle бакета удаляет брошенные multipart-загрузки спустя сутки.
Сервер скачивает S3 → HTTP потоком; Angular получает файл как браузерный Blob.

По умолчанию результаты и промежуточные данные хранятся **7 дней**. После истечения
срока скачивание недоступно; объекты удаляются, история задания остаётся.

## Конфигурация

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `DATABASE_URL` | Обязательная строка подключения PostgreSQL |
| `DATABASE_SCHEMA` | `public`; отдельная схема для независимой установки |
| `DOCKER_DATABASE_URL` | Подключение внутри Compose с хостом `postgres` |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | Первичная настройка локального PostgreSQL |
| `S3_ENDPOINT` | Локально `http://127.0.0.1:9000`; в Compose `http://s3:8333`; для AWS не задавать |
| `S3_REGION`, `S3_BUCKET`, `S3_PREFIX` | `us-east-1`, `reports`, `reports/` |
| `S3_FORCE_PATH_STYLE` | `true` для локального S3 |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Явные ключи, задаются вместе; иначе цепочка AWS credentials |
| `S3_PART_SIZE_MIB`, `S3_UPLOAD_CONCURRENCY` | `8`, `2` |
| `MAX_PERIOD_DAYS`, `RETENTION_DAYS` | `31`, `7` |
| `SEED_DEMO` | `true`; только для первой инициализации схемы |
| `PORT`, `HOST` | HTTP порт и адрес Java-приложения |

Схема приложения и таблицы Batch создаются при старте. Существующие задания,
уведомления и ссылки S3 сохраняются; миграции добавляют необходимые поля и таблицы.
Изменение `POSTGRES_PASSWORD` после создания Docker-тома не меняет пароль роли.
Для внешних сервисов задайте собственные URL и credentials через окружение.

Пустой кабинет в отдельной схеме:

```bash
SEED_DEMO=false DATABASE_SCHEMA=empty_demo npm start
```

## Проверки

```bash
npm run infra:up
npm test               # Java: unit и интеграционные проверки PostgreSQL/S3/Batch
npm run test:toolchain # выбор JDK 25 для сборки и локального запуска
npm run test:s3        # интеграционные сценарии Batch с PostgreSQL и S3
npm run test:e2e       # браузерные сценарии UI с Java backend
npm run test:migration # отдельный инструмент импорта прежней SQLite
```

Тесты используют отдельные случайные схемы и префиксы S3, удаляя только свои
данные. E2E использует порты 4310/4311 и `/usr/bin/chromium`, `CHROMIUM_PATH`
или Chromium Playwright (`npx playwright install chromium`). После аварийного
завершения runner его тестовые данные могут потребовать ручной очистки.

## Совместимость и границы

Сохранены шесть отчётов, двухшаговый мастер, поиск, фильтры, пагинация и скачивание.
Свод операций запускается только **00:00–06:00 МСК**; период ограничен 31 днём
включительно. Ответы целевых БД находятся в `backend/src/main/resources/fixtures`
и покрывают октябрь–ноябрь 2026. За период без данных создаётся Excel с заголовками.
Сервис пока рассчитан на одного демонстрационного пользователя без интеграции
авторизации настоящего ЛК.

Существующий REST API сохранён: `/api/catalog`, `/api/jobs`, `/api/jobs/:id`,
`/api/jobs/:id/download`, `/api/notifications`, `/api/notifications/read`.
Добавлен `POST /api/jobs/:id/restart`; карточка задания содержит шаги и возможность
возобновления. `/api/health` проверяет процесс, `/api/ready` — PostgreSQL и S3.
Время Batch сохраняется в UTC независимо от часового пояса хоста; UI показывает МСК.

Одноразовый импорт самых старых SQLite-установок остаётся отдельным инструментом:

```bash
npm run db:migrate:sqlite -- --source /path/to/backup.sqlite --schema imported
```

Предварительно остановите старый API и сохраните резервную копию. Целевая схема
должна быть пустой. Исходник открывается только для чтения; ID и S3-ссылки
сохраняются. Рабочий Java backend SQLite не использует.

В облачных задачах используйте существующий checkout `/workspace/report-serv`:
задачи изолированы, отдельный worktree не требуется.
